## 1. Product vision

**Product name:** BriefProof  
**Tagline:** Hire AI creators based on proof, not promises.

BriefProof is a marketplace connecting brands and agencies with AI filmmakers, AI animators, and generative content creators.

Traditional portfolios show attractive outputs but often fail to demonstrate whether a creator can follow a particular brief, maintain brand consistency, document production workflows, or explain commercial-use considerations.

BriefProof helps brands:
- Turn rough ideas into structured creative briefs using an LLM.
- Discover creators whose portfolios match a campaign's visual direction.
- Compare creators using a consistent evaluation rubric.
- Assess campaign assets for potential brand inconsistencies.
- Review creator-provided production and licensing information.
- Convert approved briefs into project milestones and acceptance criteria.

The product must feel like a credible creative technology startup, not a generic AI-generated template.

## 5. LLM API integration

Use the official OpenAI API through server-side Next.js route handlers.

Implement an organized LLM service with separate functions for:
- `generateBrief`
- `generateFollowUpQuestions`
- `matchCreators`
- `evaluateCreatorAgainstBrief`
- `generateMilestones`
- `analyzeBrandConsistency`
- `reviewLicenseChecklist`

Use structured, validated outputs wherever possible. Validate responses with Zod and handle malformed responses safely.

The creator matching feature should compare:
- Creative style.
- Portfolio evidence.
- Relevant capabilities.
- Budget compatibility.
- Availability.
- Required deliverables.
- Tool or workflow requirements.

Return ranked matches with concise explanations tied to the creator's actual profile data. Do not let the model invent creators, portfolio evidence, or qualifications.

Use this server-side environment variable:

`OPENAI_API_KEY=your_key_here`

Use a configurable model environment variable such as:

`OPENAI_MODEL=your_supported_model_name`

Choose a currently supported model compatible with the required text or vision task. Do not hardcode a guessed model name throughout the application.

Never expose the secret API key through client components, browser requests, HTML, logs, public configuration, or variables prefixed with `NEXT_PUBLIC_`.

Add:
- Server-side input validation.
- Request-size limits.
- Reasonable rate limiting.
- Timeouts and error handling.
- Sensible token limits.
- Safe logging without secrets or sensitive user content.
- Clear user-facing messages when the API key is missing or usage limits are reached.

If the LLM is not configured, the app should still load and allow users to explore sample creator profiles. Disable or clearly label AI-dependent actions and explain how to configure the feature. Do not silently substitute fake output for a failed API call.
